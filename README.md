# 기초 상식 퀴즈 게임 — E1-2

Python 기본 문법과 클래스로 구현한 콘솔 퀴즈 게임입니다. 메뉴에서 퀴즈 풀기·등록·목록·점수·삭제·기록을 선택하고 종료 후에도 퀴즈와 점수를 유지합니다. 필수 기능과 선택 과제 5개를 모두 구현했습니다.

## 주제와 선정 이유

학습 중 사용자가 선택한 **기초 상식**을 주제로 삼았습니다. 익숙한 문제로 전문 지식 조사 부담을 줄이고 Python과 Git 학습에 집중합니다. 기본 문제는 일주일의 일수·삼각형의 변·지구의 위성·얼음·대한민국의 수도입니다.

도우미가 구현과 검증을 수행했습니다. 이 이력은 사용자가 직접 작성했다는 뜻이 아닙니다. [코드 읽기 안내서](docs/코드_읽기_안내서.md)로 완성 코드를 공부할 수 있습니다.

## 실행 방법

Python **3.10 이상**과 표준 라이브러리만 사용합니다. 추가 설치 패키지는 없습니다. 현재 폴더 또는 제출 ZIP을 푼 폴더에서 실행합니다.

```sh
python main.py
```

Windows에서 `python` 대신 Python 런처가 설치되어 있으면 `py -3 main.py`를 사용합니다. 한글 출력에 문제가 있으면 `python -X utf8 main.py`로 실행합니다.

GitHub에 저장된 프로젝트를 다음과 같이 복제할 수 있습니다.

```sh
git clone https://github.com/llcckk9935/E1-2.git
cd E1-2
python main.py
```

제출 대상으로 선정한 파일과 제외 기준은 [제출 파일 목록](docs/제출_파일_목록.md)을 확인하세요.

## 기능 목록

| 번호 | 기능 | 동작 |
| --- | --- | --- |
| 1 | 퀴즈 풀기 | 문제 수 선택, 중복 없는 무작위 출제, 정오답·결과 표시 |
| 2 | 퀴즈 추가 | 문제·선택지 4개·정답 번호·힌트를 입력하고 저장 |
| 3 | 퀴즈 목록 | 등록된 문제 제목과 개수 표시 |
| 4 | 점수 확인 | 완료한 게임의 최고 점수, 미플레이 상태 안내 |
| 5 | 종료 | 저장 시도 후 종료 |
| 6 | 퀴즈 삭제 | 번호 선택, 확인 또는 취소, 삭제 결과 저장 |
| 7 | 게임 기록 | 날짜·시간, 선택 문제 수, 응답 수, 정답 수, 힌트 수, 점수, 완료 여부 |

입력 앞뒤 공백은 제거합니다. 빈 입력, 문자, 범위 밖 숫자는 안내 후 다시 입력받습니다. 정답은 1~4이며 **풀이 화면에서만 0은 힌트**입니다. 삭제 화면의 0은 취소입니다. 등록 정답 0은 허용하지 않습니다. 모든 문제를 삭제하면 풀기·목록·삭제에 빈 상태 안내가 나오며 재실행해도 빈 목록이 유지됩니다.

## 점수와 중간 종료 규칙

```python
score = max(0, round(correct / total * 100) - hints_used * 10)
```

- `total`은 선택한 문제 수입니다. 정답 비율을 100점 기준으로 계산한 뒤 힌트를 본 문제당 10점 차감합니다.
- 같은 문제의 힌트를 여러 번 보아도 한 번만 차감하며 점수는 0점 아래로 내려가지 않습니다.
- 5문제 중 4개 정답, 힌트 1회이면 70점입니다. 반올림은 Python `round()` 규칙을 따릅니다.
- 최고 점수는 끝까지 완료한 게임만 비교합니다. 첫 완료가 0점이면 최고 점수도 0점입니다. 미플레이 상태는 `null`입니다.
- Ctrl+C 또는 입력 종료(EOF) 시 진행 중 게임을 중단 기록으로 저장하고 종료합니다. 중단 점수도 선택한 전체 문제 수를 분모로 계산하며 최고 점수에는 반영하지 않습니다.
- 문제 수 선택 전 종료하면 게임 기록은 생성하지 않습니다. 등록 중 종료하면 미완성 문제는 추가하지 않습니다.

## 데이터 파일

`state.json`은 **main.py가 있는 프로젝트 루트**에 UTF-8로 저장합니다. 다른 폴더에서 절대 경로로 실행해도 저장 위치는 같습니다. 개인 플레이 기록은 Git에서 제외하고 예제만 포함합니다.

```json
{
  "quizzes": [
    {
      "question": "대한민국의 수도는 어디일까요?",
      "choices": ["서울", "부산", "대전", "광주"],
      "answer": 1,
      "hint": "한강과 경복궁이 있는 도시입니다."
    }
  ],
  "best_score": 90,
  "history": [
    {
      "date": "2026-11-22T12:00:00+09:00",
      "total": 1,
      "answered": 1,
      "correct": 1,
      "hints_used": 1,
      "score": 90,
      "completed": true
    }
  ]
}
```

위 날짜와 점수는 형식 설명용 예시입니다.
`best_score`는 미플레이 시 `null`, `history`는 기록이 없으면 `[]`입니다. `date`는 현지 시각과 UTC 시차를 포함합니다. 이전 필수 기능 형식처럼 `hint`나 `history`가 없으면 기본 힌트와 빈 기록으로 읽습니다.

파일이 없으면 기본 퀴즈로 시작합니다. JSON 문법·인코딩·필드 타입·정답 범위·기록 데이터가 잘못되면 원본을 `state.json.corrupt-날짜-시간`으로 보관하고 기본 데이터로 시작합니다. 손상 파일 보관 실패나 읽기 권한 오류가 나면 원본 보호를 위해 해당 실행의 저장을 막습니다.

임시 파일을 완성한 뒤 교체하여 저장 도중 실패해도 기존 파일을 보호합니다. 쓰기 실패는 메시지로 알리고 메모리에만 유지하므로 **저장 실패 시 종료 후 변경 유지가 보장되지 않습니다**. 여러 게임 프로세스를 동시에 실행하는 용도는 지원하지 않습니다.

## 설계 선택과 유지보수

### 클래스와 함수의 차이 및 선택 이유

`Quiz`는 문제·선택지·정답·힌트를 하나의 객체에 묶고, 생성 시 검증과
`show`, `check_answer`, `to_dict` 같은 동작을 그 데이터 가까이에 둡니다.
`QuizGame`은 퀴즈 목록, 최고 점수, 기록, 저장 경로라는 실행 상태를 소유하고
메뉴·게임 진행·저장 순서를 관리합니다. 여러 게임 인스턴스를 서로 다른
임시 저장 경로로 만들 수 있어 테스트 간 상태를 격리하기도 쉽습니다.

함수 중심으로도 같은 프로그램을 만들 수 있습니다. 그 방식은 짧은 절차를
읽기 쉽고 객체 생성이 필요 없지만, 이 프로그램처럼 공유 상태가 많으면
매 호출에 여러 값을 전달하거나 전역 변수에 의존하기 쉽습니다. 클래스는
상태와 동작의 응집도를 높이는 대신 `self`, 인스턴스 수명, 클래스 사이의
책임을 이해해야 하며 너무 큰 클래스가 되면 결합도가 높아질 수 있습니다.
따라서 상태가 필요 없는 입력 검증은 `input_helpers.py`의 함수로 유지하고,
문제 한 개의 책임은 `Quiz`, 게임 흐름과 영속성의 책임은 `QuizGame`으로
분리했습니다. 상속이나 다형성을 사용했다고 주장하지는 않습니다.

| 변경 대상 | 확인할 파일·메서드 | 검증 |
| --- | --- | --- |
| 입력 규칙 | `input_helpers.py`: `get_number`, `get_text` | 빈 값·문자·범위 검사 |
| 퀴즈 필드 | `quiz.py`: `__init__`, `to_dict`; `main.py`: `load` | 예제 JSON·기본 문제·저장 호환성 |
| 점수 규칙 | `main.py`: `play`, `record_result` | 힌트·중단·최고 점수 테스트 |
| 저장 형식 | `main.py`: `load`, `save` | 손상 복구·권한 오류·재시작 테스트 |

### JSON 선택 이유와 성능·메모리 한계

JSON은 사람이 읽을 수 있는 텍스트이고 Python의 리스트·딕셔너리를
표준 라이브러리만으로 표현할 수 있어 작은 단일 사용자 퀴즈에 적합합니다.
`quizzes`는 문제 순서를 유지하는 객체 목록, `best_score`는 아직 플레이하지
않은 상태를 구분하는 `null` 또는 점수, `history`는 날짜별 게임 기록입니다.
파일이 없을 때는 기본 문제로 시작하고, 첫 저장 동작이나 종료 시
`state.json`을 생성합니다.

반면 `json.load`는 문서 전체를 메모리에 적재하며, 현재 `save`도 문제와
전체 기록을 매번 직렬화하여 임시 파일에 기록합니다. 데이터 크기를 B라고
하면 읽기·쓰기 시간과 메모리는 대체로 O(B)입니다. 퀴즈·기록이 누적되면
시작 시간과 저장 시간이 늘어나고 객체·문자열 변환으로 원문 파일보다 더
많은 메모리를 사용할 수 있습니다. 임시 파일을 사용하므로 디스크 여유도
필요합니다. 부분 갱신·인덱스 검색·여러 프로세스의 동시 수정과 트랜잭션은
제공하지 않습니다. 원자적 파일 교체는 기존 파일 보호에 도움이 되지만
동시 실행에서 마지막 저장이 다른 변경을 덮는 문제까지 해결하지는 않습니다.

규모가 커지면 표준 라이브러리 `sqlite3`로 문제·게임 기록을 테이블로 나누고
인덱스·부분 조회·트랜잭션을 사용하는 대안을 검토합니다. 이 과제 구현은
JSON을 유지하며 DB 전환을 완료했다고 주장하지 않습니다. 손상 백업 파일은
자동 삭제하지 않으며 보관 기간·개수 제한도 없습니다. 복구 여부를 확인한
사용자가 필요한 백업을 따로 보관하고 불필요한 파일을 직접 정리합니다.

### 커밋 단위·메시지 규칙과 브랜치 전략

커밋은 하나의 설명 가능한 변경을 기준으로 나눕니다. 예를 들어 메뉴 구현,
`Quiz` 검증 추가, 출제 기능, 저장 오류 수정, README 보완을 각각 독립된
변경으로 기록하고 해당 변경에 필요한 테스트·문서는 같은 커밋에 포함합니다.
줄 수를 맞추거나 커밋 수를 늘리기 위한 형식적 분할은 하지 않습니다.
메시지는 `유형: 변경 요약`을 사용하며 `Feat: 퀴즈 출제 기능 구현`,
`Fix: 저장 실패 시 원본 보호`, `Docs: JSON 한계와 설계 선택 설명`,
`Refactor: 입력 검증 함수 분리`처럼 무엇이 바뀌었는지 적습니다.

기능별 브랜치에서 구현·검증한 뒤 main에 병합합니다. 기존 출제 기능의
`feature/quiz-play`와 `22025c6` 병합 기록은
`docs/evidence/current-git-log.txt`에 있습니다. 아래 명령으로 현재 원격과
실제 커밋 수·병합 이력을 다시 확인할 수 있습니다. 문서의 과거 커밋 수는
당시 기록이므로 현재 수와 다를 수 있습니다.

```sh
git remote -v
git rev-list --count main
git log --oneline --graph --all
git log --merges --oneline
```

### 최소 재현·예외 처리 확인

퀴즈 추가 → 종료 → 재실행 → 목록에서 추가 문제 확인 → 한 게임 완료 →
종료 → 재실행 → 최고 점수·기록 확인으로 데이터 영속성을 검증합니다.
자동 테스트의 `test_add_restart_delete_restart`와
`test_completed_game_and_restart_preserve_score_history`가 이를 확인합니다.
메뉴·추가·목록·풀이·점수 화면과 대응 로그는 위 스크린샷 표 및
`docs/evidence/run.txt`에서 확인합니다. 촬영 방식·원본 파일 정보는
`docs/screenshots/README.md`, `docs/evidence/capture-manifest.json`에 있습니다.

| 예외 사례 | 기대 동작 |
| --- | --- |
| 숫자 대신 문자·빈 입력·범위 밖 번호 | 안내 후 재입력 |
| Ctrl+C 또는 EOF | 안내 후 가능한 상태 저장, 미완성 등록 제외 |
| JSON 손상 | 원본 백업 후 기본 문제, 백업 실패 시 저장 금지 |
| 파일 읽기 권한 오류 | 원본 보호를 위해 해당 실행의 저장 금지 |
| 파일 쓰기 실패 | 안내하고 메모리 유지, 기존 저장 파일 보존 |

실제 터미널에서는 메뉴나 풀이 중 Ctrl+C를 누른 후 안내와 저장 상태를
확인할 수 있습니다. 자동 테스트는 예외 주입과 EOF 서브프로세스로
검증하며 물리적인 키 입력을 검증한 것으로 간주하지 않습니다.
