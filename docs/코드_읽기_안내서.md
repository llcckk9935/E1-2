# 완성 코드로 공부하기

## 읽는 순서

1. `input_helpers.py`: 이전에 배운 입력·공백 제거·정수 변환·범위 검사가 메뉴에서 어떻게 재사용되는지 확인합니다.
2. `quiz.py`와 `default_quizzes.py`: 문제의 설계도인 클래스와 실제 다섯 문제를 연결합니다.
3. `main.py`: `run → play → record_result → save` 순서로 따라갑니다.
4. `add_quiz`, `show_list`, `delete_quiz`: 목록이 언제 바뀌는지 확인합니다.
5. `load`와 `state.json`: 파일의 글자가 실행 중 객체로 어떻게 바뀌는지 확인합니다.
6. `tests/test_game.py`: 테스트 이름을 보고 예외 상황을 복습합니다.

직접 실행은 선택 사항입니다. 코드를 읽으며 결과를 예상하는 방식으로도 공부할 수 있습니다.

## 배운 문법과 실제 위치

| 개념 | 코드에서 찾을 곳 | 뜻 |
| --- | --- | --- |
| 변수 | `correct = 0` | 정답 수에 이름을 붙여 기억합니다. |
| `int` (인트, 정수) | `int(text)` | 입력 글자를 계산 가능한 숫자로 바꿉니다. |
| `str` (스트링, 문자열) | `question` | 문제와 선택지의 글자입니다. |
| `bool` (불, 참·거짓) | `completed`, `hint_used` | 완료와 힌트 사용 여부입니다. |
| `list` (리스트, 목록) | `self.quizzes` | 여러 문제를 순서대로 보관합니다. |
| `dict` (딕셔너리, 이름과 값의 짝) | `Quiz.to_dict()` | 저장할 데이터에 항목 이름을 붙입니다. |
| 조건문 | `run`의 `if/elif` | 메뉴에 맞는 기능을 실행합니다. |
| `while` (와일, 조건 반복) | `get_number`, `run` | 올바른 입력이나 종료 선택까지 반복합니다. |
| `for` (포, 항목 반복) | `show_list`, `play` | 목록의 문제를 하나씩 처리합니다. |
| 함수와 반환 | `return number` | 검사한 정수를 호출한 곳에 돌려줍니다. |
| 클래스와 객체 | `Quiz`, `Quiz(...)` | 설계도와 그 설계도로 만든 실제 문제입니다. |
| `__init__` (이닛, 초기 설정) | 두 클래스의 생성 부분 | 객체의 초기값을 준비합니다. |
| `self` (셀프, 현재 객체) | `self.answer` | 지금 다루는 문제나 게임을 가리킵니다. |
| 속성과 메서드 | `quiz.answer`, `quiz.check_answer()` | 객체가 가진 값과 수행하는 동작입니다. |
| JSON (제이슨, 데이터 글자 저장 형식) | `json.dump`, `json.load` | 객체를 파일에 저장하고 읽습니다. |
| `try/except` (트라이·익셉트, 시도·오류 처리) | `load`, `save`, `run` | 입력·파일 오류가 나도 안내하며 처리합니다. |

## 정상 입력과 정답은 다릅니다

`get_number(..., 1, 4)`가 2를 반환했다는 것은 **허용된 번호**라는 뜻입니다. 정답이라는 뜻은 아닙니다. `quiz.check_answer(2)`에서 실제 정답 번호와 비교하여 참 또는 거짓을 돌려줍니다.

풀이 화면은 힌트 때문에 0~4를 받습니다. 0이면 힌트를 표시하고 다시 입력받으며 1~4를 골라야 채점합니다. 문제 등록은 정답 1~4만 허용합니다.

## 한 번의 게임을 따라가기

두 문제를 골라 첫 문제만 맞히고 두 번째 문제에서 힌트를 한 번 보면 다음과 같이 처리합니다.

1. `get_number`가 문제 수 2를 반환합니다.
2. `random.sample`이 서로 다른 두 문제를 고릅니다. 원래 문제 목록은 바뀌지 않습니다.
3. `for`가 문제를 표시하고 `check_answer`로 정답 수를 셉니다.
4. `hint_used`는 문제마다 `False`로 다시 시작합니다. 같은 문제에서 0을 여러 번 눌러도 `hints_used`는 한 번만 증가합니다.
5. `record_result`는 `round(1 / 2 * 100) - 1 * 10`, 즉 40점을 계산합니다.
6. 날짜와 결과를 `history`에 추가하고 완료한 게임이면 최고 점수를 비교합니다.
7. `save`가 퀴즈·최고 점수·기록을 파일에 저장합니다.

## 메모리와 파일

`self.quizzes.append(...)`는 실행 중 메모리만 바꿉니다. 종료 후에도 유지하려면 `save`가 파일에 써야 합니다. 다음 실행에서 `load`가 파일을 읽고 `Quiz` 객체를 다시 만듭니다.

`None`은 완료한 게임이 없다는 표시입니다. 0점은 실제 게임을 완료한 결과입니다. JSON에서는 `None`이 `null`, `True`가 `true`로 저장됩니다.

처음에는 `load`와 `save`에서 정상 파일을 읽고 쓰는 줄부터 보세요. 다음에는 파일 없음·손상·권한 오류를 읽습니다. 임시 파일 교체는 쓰기 실패 때 이전 파일을 보호하는 장치입니다.

## Git 변경 이력

Git(깃)은 변경 이력을 관리합니다. 커밋(commit)은 변경을 하나의 기록으로 남기는 동작입니다. 퀴즈 출제는 `feature/quiz-play` 브랜치에서 구현한 뒤 `main`에 병합했습니다.

| 명령 | 하는 일 |
| --- | --- |
| `init` (이닛) | 변경 이력 저장소를 만듭니다. |
| `add` (애드) | 다음 기록에 포함할 변경을 고릅니다. |
| `commit` (커밋) | 선택한 변경을 기록합니다. |
| `checkout` (체크아웃) | 브랜치를 만들거나 전환합니다. |
| `merge` (머지) | 다른 브랜치의 변경을 합칩니다. |
| `push` (푸시) | 이력을 원격 저장소로 보냅니다. |
| `clone` (클론) | 저장소와 이력을 별도 폴더로 복제합니다. |
| `pull` (풀) | 원격 변경을 가져와 현재 브랜치에 합칩니다. |

로컬 실습과 GitHub 업로드는 별개입니다. 실제 수행 위치와 업로드 상태는 `제출_상태.md`를 확인하세요.

## 짧은 복습 질문

- `abc`를 입력하면 어디서 다시 입력받을까요?
- 허용 번호 3을 입력하는 것과 정답을 맞히는 것은 어떻게 다를까요?
- `correct += 1`을 조건문 밖으로 옮기면 어떤 일이 생길까요?
- 힌트를 두 번 봐도 왜 한 번만 감점할까요?
- 등록 중 종료하면 왜 미완성 문제가 남지 않을까요?
- 저장하지 않고 종료하면 무엇이 사라질까요?
- 최고 점수 `None`과 0은 어떻게 다를까요?
- 중단 기록에서 `total`과 `answered`는 왜 다를 수 있을까요?

정답 힌트: 입력 반복문, 입력 검사와 채점, 조건 범위, 문제별 참·거짓 변수, 전체 입력 후 추가, 메모리와 파일, 미플레이와 완료, 선택 수와 실제 응답 수입니다.
