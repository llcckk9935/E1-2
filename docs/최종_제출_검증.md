# 제출 요건 보완 기록

## 원격 저장과 개발 이력

GitHub 공개 저장소는 `https://github.com/llcckk9935/E1-2`입니다. 보완 시작 시 실제 원격 `main`은 `ac9950d2d0e85f8a788da7738ed5276925c9db36`, 출제 브랜치는 `29d188fae7bc6797a880887a33db9b91b5afadfe`였으며 `docs/evidence/remote-check.txt`에 확인 결과를 보관했습니다.

GitHub에서 새로 clone한 `submission/`에는 기존 개발 커밋 22개와 병합 이력이 보존되었습니다. 이 폴더는 `.git`이 있는 일반 작업 저장소이므로 해당 폴더에서 `git status`, `git log`, `git remote -v`를 사용할 수 있습니다.

보완본을 commit·push하고 원래 작업본에서 pull하는 후속 과정은 로컬 전용 `outputs/Complete-Submission.ps1`에서 수행합니다. 실제 실행 결과는 `docs/evidence/github-practice.txt`에 추가합니다. 이 기록이 없다면 보완본의 원격 실습 완료를 주장하지 않습니다. 기존의 `git-practice.txt`는 로컬 원격 대상 실습이므로 GitHub 실습 증거와 구분합니다.

부모 작업 폴더의 처음 생성된 `.git`은 비어 있었고 환경 정책상 도우미가 수정할 수 없었습니다. 마무리 스크립트는 기존 이력이 있는지 먼저 확인한 뒤, 비어 있을 때만 `outputs/git-history`의 보존된 이력을 연결합니다. 사용자 이력이 발견되면 덮어쓰지 않고 중단합니다.

- 새 GitHub 복제본에서 자동 테스트 23개가 통과했습니다.
- 기존 게임 코드는 변경하지 않았습니다.
- 퀴즈 등록·목록·풀이·힌트·결과·최고 점수·재시작 데이터 유지 화면을 실제 실행으로 촬영했습니다.
- VS Code에서 실제 개발 환경 출력과 실제 Git 그래프를 확인하는 화면을 촬영했습니다.

- 원본 JPG와 실행 코드의 SHA-256은 `docs/evidence/capture-manifest.json`에 기록했습니다.

## 확인 범위의 한계

Ctrl+C 처리는 자동 테스트에서 `KeyboardInterrupt` 예외를 주입해 검증했습니다. 일반 터미널에서 물리적으로 Ctrl+C를 누르는 동작을 이번 캡처로 검증했다고 주장하지 않습니다. 학습자가 코드를 스스로 설명할 수 있는지와 별도 교육 플랫폼의 접수 여부는 검증하지 않았습니다.

최종 ZIP·bundle·검증 JSON은 마무리 스크립트가 실제 원격 확인 후 다시 생성합니다. 과거 `dist/verification.json`을 현재 상태의 증거로 재사용하지 않습니다.
